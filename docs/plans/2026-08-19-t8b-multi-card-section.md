## 0. なぜ範囲が変わったか

当初の T8b は要求 #4「主副カード合印時、A の合計・B の合計を記録に入れない」
＝ **多く記帳してしまうこと**への兜底だった。

**真票で実測したら、起きていたのは逆だった。** 2026-08-19、アメックス 8 頁
（主副カード合印）を `local_test.py` に通した結果:

| | 金額 |
|---|---|
| 記帳合計 | 366,162 |
| 券面「今回ご利用・ご請求金額合計」 | 512,833 |
| **差額** | **−146,671** |

内訳は 1 円のずれもなく説明がつく:

```
主カード A（西久保 智宏 様）今月ご利用額合計   350,218  → 全行記帳された
副カード B（西久保 絵理 様）今月ご利用額合計   162,615
  ├ p5 後半の 11 行                          146,671  → **1 行も記帳されず**
  └ p6 の 4 行                                15,944  → 記帳された
                                            ─────────
記帳 350,218 + 15,944 = 366,162 ／ 券面 512,833
```

**#4（多く記帳する）は実測で起きていない。** 探針で確認したところ
`rows` 8 行は全て真の明細で、合計 350,218 は正しく `printed_totals` に
入っていた。prompt の「合計行・小計行を rows に入れないでください」は効いている。

→ **T8b は「多く記帳する」対策から「取りこぼしを無くし、取りこぼしを
検出可能にする」対策へ変わる。**

## 1. 根因（実測で確定。推測ではない）

### 1.1 直接原因: prompt の 2 条の作用域が衝突している

| # | 指令 | 位置 |
|---|---|---|
| ① | 「この 1 ページに見えているカード **1 枚分だけ**を報告してください」 | `card_prompts.py:154`（【最重要】の筆頭） |
| ② | 「`rows_on_page` ＝ 券面に印字された明細行の総数（**取得できた数ではなく券面に見えている数**）」 | `card_prompts.py:62` |

p5 の券面には 19 行（A の 8 行 ＋ 区画切替 ＋ B の 11 行）が印字されている。
Gemini は ① を使って ②「見えている」の範囲を**1 枚分に限縮**した。

探針の実測（2026-08-19、p5 を 1 回）:

```
card.member_no    = '**********-71008'   ← 主カード A（副カードは 71016）
rows              = 8 行                  ← A の行のみ
rows_on_page(申告) = 8                     ← 券面 19 行に対し 8 と申告
printed_totals    = [西久保 智宏 様 今月ご利用額合計 350,218]  ← A のみ
sections          = 1 個                   ← 区画を 1 つしか認識していない
```

**Gemini は失敗していない。指令どおりに動いた結果、B が消えた。**

#### 対立仮説「OCR 入力欠落」の排除（Codex HIGH-1 を受けて裏取り）

同じ症状（`rows=8 / rows_on_page=8 / sections=1`）は「PaddleOCR が
p5 下半分を読めていない」でも起こりうる。**実測で排除済み** ——
p5 の PaddleOCR 生テキストには区画切替も副カードの行も**入っている**:

```
西久保 智宏 様今月乙利用额合計
350,218
今月ご利用额
西久保
絵理様
会员番号
016                    ← 副カードの会員番号（末尾 71016 の断片）
12月21
ソフトバクモイまとて支払い東京都港区
10,000                 ← 副カード 1 行目
…（以下 11 行が続く）
```

入力には在り、出力からだけ消えている。よって欠落は **Gemini の抽出段**で
起きており、prompt の作用域限縮という説明と整合する。
（既定戦略は C ＝ PaddleOCR テキスト ＋ 原図の交差検証。A/B でも
テキストは同じものが渡る。）

### 1.2 なぜ無音になったか: 申告と取得が「自洽」してしまう

`card_salvage.detect_shortage` は `rows_on_page`（申告）と実際の行数を比べる。
申告 8・取得 8 なので**一致 → 警告ゼロ**。

`rows_on_page` の設計自体は正しい。契約は物理アンカー（券面）であり、
T5 の注釈も「『取得できた数』を数えさせると検出が循環して意味を失う」と
明記している。**壊れたのは契約ではなく、①による作用域の限縮**である。

### 1.3 第 3 の防護（検算）も現状は効かない

- `card_reconciliation` は**生産未接線**（参照はテストのみ）
- 接線しても、主副カード券面は `SECTION_CURRENT_USAGE` に
  350,218 / 162,615 / 512,833 の 3 値が並び `len(current)>1` →
  「合計不整合」＝**検算不能**（既知 P1）

**3 層すべてが同時に無効。** 顧客が券面と突合しない限り誰も気づかない。

## 3. 核心設計課題（Codex 評審の主論点）

### 3.1 ① をどう直すか —— 消してはいけない

① は F-1（1 つの PDF に 3 社分の明細が混在する）への対策であり、
**跨頁の推測補全を禁じる部分は正しい**。消すと別の事故が戻る。

分けるべきは 2 つの軸:

| 軸 | あるべき指示 |
|---|---|
| **頁内**の複数区画 | **全部報告する**（各行がどの区画に属するかを記す） |
| **跨頁**の推測補全 | **従来どおり禁止**（他頁の情報で補わない） |

現行の ① はこの 2 軸を「1 枚分だけ」の一語で潰している。

### 3.2 取りこぼしを検出可能にする 2 案

| 案 | 内容 | 評価 |
|---|---|---|
| **甲** | `rows_on_page` の文言に「**頁全体・全区画の合計**」を明示し、区画限縮を禁じる | **必要だが不十分**。Gemini が再び限縮したら再発し、検出は自己申告依存のまま |
| **乙** | **プログラム側**で区画切替マーカー（`今月ご利用額 <氏名> 様` ＋ 会員番号）の出現回数を OCR テキストから数え、`sections` 数と突合。乖離したら監査タブへ警告 | **採用**。検査器が被検査者（Gemini）の外に出る |

**甲＋乙の両方を採る。** 甲だけでは「被検査者の自己申告を信じる」構造が残り、
乙だけでは取りこぼし自体は直らない。

#### 乙の検査は 2 段にする（Codex HIGH-3）

`marker_count > len(sections)` だけでは**まだ沈黙する抜け道**がある ——
Gemini が `sections` は 2 個返しつつ rows は主カードの 8 行だけ、という形。
`2 > 2` は偽なので警告ゼロになる。

`rows[]` には既に **`sec`（その行が属する sections の index）** が定義済み
（`card_prompts.py`）。これを使う:

| 検査 | 発火条件 | reason |
|---|---|---|
| 区画数の突合 | `marker_count > len(sections)` | `section_undercount:<検出>/<申告>` |
| **行の区画分布** | `marker_count >= 2` かつ `rows[].sec` の distinct 数 <= 1 | `section_rows_missing:<検出>/<distinct>` |

後者が抜け道を塞ぐ。「区画は 2 つ在ると認識しているのに、行は片側にしか
属していない」は構造的に異常である。

#### 検出器は三値にする（Codex HIGH-4）

OCR テキスト検査は Gemini の外だが、**同じ page bytes / OCR 品質に依存する**。
PaddleOCR が下半分を落とした・Vision 兜底で `ocr_text` が空、という場合は
検出器も沈黙する。したがって:

- 検出結果は `0 / 1+ / unknown` の三値
- **クレカ明細らしさが在るのにマーカーを 1 つも取れない頁**は
  `section_detection_unknown` を監査タブへ

「取りこぼしが二度と無音にならない」とは書けない。書けるのは
**「Gemini の抽出段の取りこぼしは無音にならない。OCR 入力段の欠落は
unknown として可視化する」**まで。

**設計原則（Plan に明文化する）**:
> 検算の基準を被検査者自身の申告から取ってはならない。
> 被検査者が漏らしたものは、その申告にも現れない。

`rows_on_page` は物理アンカーとして設計されていたが、①がそれを申告依存へ
引き戻した。乙はこの原則を**構造で**担保する。

### T8b-2: 区画数の突合と警告（RED → GREEN）

- 変更: 下記 3 つの条件で監査タブへ警告。**記帳は止めない**
  （IP-401: 取れている行を落とさない）。
  1. `marker_count > len(sections)` → `section_undercount:<検出>/<申告>`

### T8b-3: prompt の作用域を分離（**T8b-1/2 が緑になってから着手**）

**二段構えにする理由**（Codex MEDIUM-5）: `card_entries` は
`raw_data["card"]` を**1 個しか持たず、行ごとの会員 ident を消費しない**。
prompt を緩めて Gemini が複数カードの行を返すようになっても、下流は
それらを単一 card として扱う。先に検出・監査（T8b-1/2）だけ入れて
「どれだけ取りこぼしているか」を可視化し、その実データを見てから
prompt を触る。prompt は本番稼働中で全クレカ顧客に影響する。

文言も限定する: 「同一頁内の**同一発行体・同一明細書**に印字された複数の
会員区画は全部報告する」。別会社・別明細書の混在（F-1）は従来どおり除外。


- 変更: `card_prompts.py:154` の ① を 2 文に割る。
  「**同一頁に複数のカード区画があれば全部報告する**（各 row に区画を示す）」
  ＋「**他頁の情報で推測補完しない**」。
  併せて `rows_on_page` に「頁全体・全区画の合計」を明示（甲）。
- **DoD**:
  - p5 を 3 回投げて `rows` が 19 行前後・`rows_on_page` が 19 になる
  - `sections` が 2 個になる
  - **回帰**: 単一カード券面（アメックス 6 頁）の rows 数が変わらない
  - **回帰**: nimoca（transit_ic）の prompt は触らない

## 9.5 趙の拍板（2026-08-19）＋ 信号設計の実測

**3 点とも拍板済**: (1) prompt を触ってよい（二段構え・単一カード券面の回帰先行）
(2) 多シグナルのスコア化（単一シグナルに押さない）(3) 警告は監査タブのみ。

### 信号の実測（p1〜p6・PaddleOCR 生テキスト）

| 頁 | 「今月ご利用額」系 | うち「合計」付き | **区画頭** | card_keys |
|---|---|---|---|---|
| p1 | 1 | 0 | 1 | 71008 |
| p2–p4 | 0 | 0 | 0 | 71008 |
| **p5** | **2** | **1** | **1** | **71008 のみ** |
| p6 | 0 | 0 | 0 | — |

**判定式**: 区画頭 ＋ 合計行 >= 2 → その頁で区画が切り替わっている。
p5 は 1+1=2 で命中。p1 は 1+0=1 なので単一区画（誤報しない）。

**会員番号は主判定に使えない**（実測）: p5 の `card_keys` は主カードの
71008 しか取れておらず、副カードの 71016 は OCR が `016` としか読めなかった。
Codex MEDIUM-6 の懸念がそのまま実データで再現している。会員番号は
**補助シグナル**に留め、主判定は上の構造特徴に置く。

**OCR の崩れ方**（テスト fixture が再現すべき形）: 「ご」→「乙」、
「額」→「额」、「明細」→「明细」。骨格 `今月.{0,2}利用[额額]` で吸収する。

## 10. 辯論記録（Codex 評審 ラウンド 1・2026-08-19）

総合判定 **NO**。8 件の指摘のうち **7 件を全面採納、1 件を条件付きで解消**。

| # | 深刻度 | 指摘 | 裁決 |
|---|---|---|---|

### #1 について: 駁回ではなく「証拠を出して条件を消した」

Codex の指摘は正しい —— **本番戦略が A/B なら Gemini は OCR テキストしか
見ないので、テキスト自体に副カードが無ければ prompt 衝突では説明できない**。
Plan にその裏取りが書かれていなかったのは私の不備。

ただし証拠は取得済みだった（Plan に転記していなかっただけ）。p5 の
PaddleOCR 生テキストには区画切替も副カード 11 行も入っている（§1.1 に転記）。
**入力に在り出力から消えている**ので、欠落は抽出段で起きている。
よって「最有力仮説へ格下げ」の条件は成立しない。

**この 1 件は Codex へ回餵しない。** 技術的な対立ではなく、
私が証拠を Plan に書き忘れていただけで、書けば条件が消える性質のもの。
