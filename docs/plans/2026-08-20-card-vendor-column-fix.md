### 1.4 券面の欄構成（PaddleOCR 実測。Codex は券面を読めないので本節が唯一の根拠）

**TS CUBIC p4（給油明細）— 8 欄。店名欄の名は「ステーション名」**

```
ご利用年月日 / ご利用内容（備考）/ 数量 / 単価(円) / ご請求金額(円)
/ 内、消費税(円) / 内、軽油引取税(円) / ステーション名
```

実データ: `レギュラー 34.13 5495 500 バイパス奈良中央SS`
→ Gemini は「ご利用内容」を merchant、「ステーション名」を note に入れた。

**TS CUBIC p6（ETC 明細）— 4 欄。店名欄が無い**

```
利用年月日 / 利用内容 / ご請求金額（円）/ 摘要
```

実データ: `ETC 東大阪入 … 東大阪荒本 軽自動` `ETC 紫川 … 黒崎東出口 普通車`
→ **F=入口、T=出口＋車種。取り違えではなく両方が券面の実内容**。約 55 行。

**ENEOS 個人カード p2 — 店名欄の名は「ご利用店名」**

```
利用年月日 / 摘要 / ポイント / ご利用店名 / 利用金額(円) / お支払方法 / 今回回数 / 今回ご請求金額(円)
```

**→ 券面によって店名欄の名称が違う（「ステーション名」vs「ご利用店名」）。**
prompt で片方だけ書くともう片方は直らない。これが案 A を採らない実証的理由。

## 2. 根因

`card_prompts.py:103`

```
"merchant": ('"福北高速 ＥＴＣ後納分"', "利用店名・摘要の主行"),
```

**定義そのものが「利用店名 または 摘要」を許している。** 給油所券面は
両欄が独立して印字されるため、Gemini が摘要欄（油種）を「主行」と
解釈した。**指示違反ではない。**

消費側の結線（現状）:

- `card_entries.py:480` `"debit_vendor": str(row.get("merchant") or "").strip()` → **F列**
- `card_entries.py:447-449` `_description` も merchant を使う → **S列**
- `card_entries.py:452` `_memo` は `note` を使う → **T列**

## 3. 採用案 = D（表示欄の組み替え）

**Gemini にも raw の契約にも触れない。** `_base_entry` が表示欄を組む
その場所だけで、給油所型の取り違えを是正する。

### 3.1 判定

```
_looks_swapped(row) :=
    NFKC(merchant) が _GOODS_LABELS のいずれかで始まる
    かつ note が非空
```

`_GOODS_LABELS` = 油種・役務語（`レギュラー` `ハイオク` `軽油` `ケイユ`
`フケイユ` `灯油` `洗車` `手洗洗車` `オイル` `タイヤ` `パーツ` `作業`
`ガソリン` `プレミアム`）。NFKC は既存の `card_entries._norm` を使う。

**「T が店名らしいか」は条件に入れない。** 実測で `CSCネオス塚口` が
店名接尾辞（店/SS/セルフ/営業所/支店）を持たず、この条件を足すと
「パーツ」「作業」3 行を取りこぼす。脆い発見的規則を重ねない。

### 3.2 動作（表示欄のみ）

| 欄 | 通常行 | 取り違え行 |
|---|---|---|
| F（借方取引先） | merchant | **note**（店名） |
| S（摘要） | merchant ＋ 外貨 suffix | **`note merchant`** ＋ 外貨 suffix（趙拍板②） |
| T（仕訳メモ） | note ＋ 手書き ＋ 却下科目 | **変更なし** |

T列を触らないのは、原文の文脈を失わせないため（Codex 評審 P1）。
F と重複するが、重複は誤りではない。

### 3.3 触ってはいけないもの

- **raw の row 辞書**。`detail_lines_from_raw`（`card_entries.py:332`）が
  読む検算側の逐語まで変わる（Codex 評審 P1）。
- **`_row_text`（`card_entries.py:236`）**。記帳軸 kind の判定に使う。
  表示の都合で分類が動いてはいけない。
- **ETC 行**。§1.4 のとおり取り違えではない。語彙表に ETC 語を入れない。

## 4. 却下した案と理由

| 案 | 内容 | 却下理由 |
|---|---|---|
| A | prompt の merchant 定義を書き換える | 券面ごとに店名欄の名称が違う（§1.4）。ETC 頁には店名欄が無いので fallback 規則が必須になり、それでも 335 行への影響を真票実行でしか測れない |
| B | `shop_name` を新設して分離 | 出力形状が変わり既存の真票実測の前提が一部無効になる。改修面が 5 箇所以上 |
| C | raw の merchant と note を入れ替える | 検算側（`detail_lines_from_raw`）の逐語まで変わる（Codex 評審 P1） |

**趙の拍板（2026-08-20）: D。S列は「店名 商品名」。**

## 5. 受入基準（Codex 評審を容れて全面改訂）

**検証は凍結した raw JSON に対して行う。** Gemini を再実行すると
無関係な文字列まで揺れ、prompt 由来か抖動か切り分けられない
（Codex 評審 P1）。

| # | 判定 | 方法 |
|---|---|---|
| V1 | 既知 20 行の F列が**その行の元 T列と一致**する | 「油種語が 0 件」では不十分（空欄・OCR ゴミでも通る）。逐値比較 |
| V2 | S列が `店名 商品名` になる | 例: `バイパス奈良中央SS レギュラー`。外貨行は suffix が末尾に残る |
| V3 | T列が 1 バイトも変わらない | 全 355 行 |
| V4 | **335 行の F/S/T が逐字同一** | 凍結 raw から builder を回して改修前後を比較 |
| V5 | ETC 行の F列が**逐値**同一 | 件数一致では不十分（`ETC` と `ETC通行料金/N西日本` は別物） |
| V6 | 分類が動かない | `_row_text` 由来の kind / line_kind / 税区分が全行同一 |
| V7 | 全量テスト緑 | 1280 tests |

### 5.1 新規テストで固定する形

給油行 / ETC 行 / 通常店名行 / 外貨行 / 占位行 の 5 形態について
F・S・T を逐語 assert する。特に **ETC 行と通常店名行は「変わらないこと」**
を両方向で固定する（T6-7 が踏んだ「顧客の帳簿の見た目が黙って変わる」
失敗様式の再発防止）。

## 6. 非目標 / 持ち越し

- **未知の商品・役務語は依然として漏れる。** Codex は「未一致の疑わしい行を
  記録して漏れを可視化せよ」と提案したが、出力を汚すと V3/V4 の逐字比較が
  複雑になるため**本件では実装しない（P2 として持ち越し）**。
- カード名（補助科目）の頁跨ぎ欠落（348 行中 168 行が空）。別件。
- 日付の頁跨ぎ継承（T8d、実装済・回帰未実施）。
- **軽油引取税の分離**。TS CUBIC p4 の券面には「内、軽油引取税(円)」欄が
  実在し（500 / 45 / 488 / 428 / 447 / 332 …）、現在これを分離せず行全体を
  課対仕入10% にしている。**P1 として別件記録**。
- 金額・科目・税区分・日付。本件では一切触れない。
